# Локальная диагностика серверов

Модуль `ServerDiagnosticsStore` пишет структурированные события в приватную область приложения:

`files/server-diagnostics/server-diagnostics.jsonl`

События включаются в обычный ручной экспорт диагностических логов (кнопка экспорта в разделе диагностики). Ничего автоматически не отправляется в сеть; серверной части и удалённой отправки нет.

## Сейчас записывается

- результат TCP-проверки сервера сканером;
- измеренная длительность TCP-подключения;
- успех/ошибка и фиксированный код ошибки;
- тип протокола из allowlist;
- непрозрачный идентификатор сервера — SHA-256 от адреса и порта, усечённый до 12 байт.

Это **не** тест пропускной способности: поля скорости, DNS и handshake предусмотрены схемой, но пока не заполняются. Следующий этап — добавить явный тест скорости с ограниченным объёмом данных и отдельно измерять download/upload; не измерять пользовательский трафик.

## Ограничения и приватность

- JSONL содержит только типизированные поля; адрес, имя профиля, UUID, пароль, ключи Reality, subscription URL и произвольные сообщения исключены из схемы.
- В журнал не пишутся тексты исключений — только фиксированные коды.
- Текущий файл ограничен 2 MiB, предыдущий файл при ротации заменяется.
- Ошибка записи диагностики не должна останавливать VPN.
- Экспорт выполняется только по действию пользователя через существующий экспорт логов. Перед отправкой файл можно открыть и проверить.

## Пример записи

```json
{"schemaVersion":1,"timestamp":1792860000000,"event":"probe_completed","runId":"run_123","serverId":"a1b2c3d4e5f6","protocol":"hysteria2","stage":"tcp_connect","dnsMs":null,"connectMs":180,"handshakeMs":null,"downloadMbps":null,"uploadMbps":null,"durationMs":null,"bytesDownloaded":null,"bytesUploaded":null,"success":true,"errorCode":null}
```

Пример иллюстративный, не реальное измерение.
