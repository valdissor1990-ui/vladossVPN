# Контрибьютинг

## Лицензия и границы проекта

- Исходный код проекта распространяется по GPL-3.0-or-later. Любые производные работы должны сохранять совместимость с этой лицензией.
- Не удаляйте и не сокращайте `LICENSE`, `THIRD_PARTY_NOTICES.md`, уведомления в `app/src/main/assets/licenses/` и сведения об исходных ревизиях.
- Графика бренда vladossvpn защищена отдельным уведомлением в `docs/branding/NOTICE.md`. Не изменяйте, не копируйте и не распространяйте её без письменного разрешения.
- Версия `libbox.aar` и SHA-256 в `scripts/download_libbox.sh` закреплены. Не меняйте их и не обходите проверку ради успешной сборки.

## Требования к изменениям

1. Сначала определите владельца логики и существующие тесты. Избегайте дублирования сервисов, парсеров и менеджеров.
2. Для Kotlin используйте официальный стиль Kotlin, явные типы на публичных границах и небольшие функции с одной ответственностью.
3. Не блокируйте главный поток. Для асинхронной работы используйте корутины и структурированную отмену.
4. Изменения VPN-жизненного цикла проверяйте на start/stop, повторном подключении, смене сети, отзыве разрешения и закрытии TUN.
5. Изменения парсеров покрывайте позитивными, негативными и граничными тестами. Не используйте реальные UUID, ключи и рабочие подписки в тестовых данных.
6. Не добавляйте секреты в исходники, ресурсы, BuildConfig, логи, CI-артефакты или сообщения об ошибках.

## Логи и безопасность

Запрещено журналировать UUID, пароли, private keys, Reality short ID/private key, URL подписки с токенами, содержимое трафика и полные IP-адреса серверов/клиентов. Используйте маскирование и безопасные идентификаторы. Подробности — в [модели угроз](THREAT_MODEL.md).

## Тестирование перед PR

Из корня репозитория:

```bash
./gradlew :app:testDirectDebugUnitTest
./gradlew :app:assembleDirectDebug
./gradlew :app:generateLicenseReport
```

Если Gradle Wrapper JAR отсутствует, используйте поддерживаемый CI bootstrap из `.github/workflows/build.yml`; не скачивайте непроверенный wrapper. Для полной сборки предварительно выполните `./scripts/download_libbox.sh`.

## Коммиты и Pull Request

- Предпочитайте короткие коммиты с глаголом: `Fix UDP route validation`, `Add parser regression tests`.
- Один PR — одна логическая задача. Укажите проблему, решение, риски, затронутые протоколы и способ ручной проверки.
- При изменении UI приложите скриншоты до/после; при изменении соединения — обезличенные диагностические логи.
- Не сливайте PR при красных CI-проверках. Исправьте причину, а не отключайте тест или проверку лицензий.
- Любое обновление зависимостей должно сопровождаться пересмотром лицензий и обновлением `THIRD_PARTY_NOTICES.md` при необходимости.
