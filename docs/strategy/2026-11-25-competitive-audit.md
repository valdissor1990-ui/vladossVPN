## 3. Где уже обошли конкурентов

### 3.1 Проверка сервисов, а не только пинга

vladossVPN проверяет доступность конкретных сервисов через активный mixed inbound и честно разделяет:

- `REACHABLE` — контрольный запрос прошёл;
- `ANSWERED` — сервер ответил, но не 2xx;
- `UNKNOWN` — проверить не удалось;
- `VPN_OFF` и `TRANSITION` — проверка неприменима.

У Happ, Hiddify, v2rayNG и NekoBox пользователь видит задержку сервера или результат одного URL. Никто не показывает матрицу «YouTube работает, ChatGPT нет». Это прямое преимущество в главном сценарии: «VPN подключён, но что-то не открывается».

### 3.2 Разный зарубежный сервер для выбранных приложений

`DualPathStore` позволяет отправить выбранные приложения через отдельный зарубежный outbound, пока остальные работают через основной. У конкурентов есть per-app VPN и обход, но нет выбора отдельного сервера для группы приложений. Это ближе к «профилям под задачу», чем обычный split tunneling.

### 3.3 Умный выбор сервера с доказательствами

`ScoringEngine`, `DeepProbeEngine`, `HealthMonitor` и `AutoSwitcher` оценивают не только TCP-задержку, но и реальный прокси-ответ, историю падений и стабильность. У большинства конкурентов выбор — «наименьший пинг» или ручной. vladossVPN ближе к промышленному health-check.

### 3.4 Приватность по умолчанию

Happ в документации прямо пишет: HWID включён по умолчанию, а подписка может запретить пользователю его отключать. В vladossVPN передача HWID и метаданных устройства выключена по умолчанию и требует явного согласия. Плюс нет встроенных подписок и серверов, нет телеметрии, журналы очищаются от секретов.

### 3.5 Прозрачность цепочки поставок

В репозитории есть CodeQL, SBOM, dependency audit, фиксированный SHA-256 для `libbox.aar`, подписанные релизы и проверка отсутствия выведенных ядер. Для аудитории, которая выбирает клиент после блокировок, это сильнее, чем «open source» без артефактов.

### 3.6 Русская маршрутизация с деградацией

Пресет `BYPASS_RU` использует локальные `.srs`-правила и при их отсутствии честно откатывается в `BYPASS_LAN`, а не ломает подключение. У конкурентов есть geoip/geosite, но настройка обычно сложнее.

## 4. Где ещё нужно обойти

### 4.1 Платформы и ТВ — главный разрыв

vladossVPN — только Android. Hiddify и Happ работают на Android, iOS, Windows, macOS, Linux; Hiddify и v2RayTun поддерживают Android TV. Пока это ограничивает аудиторию и мешает сценарию «телефон + ТВ + ноутбук».

**Что делать:** сначала шлюз для ТВ/ноутбука (волна 2), затем отдельное решение для ТВ. Полноценный порт на iOS/десктоп — стратегическое решение, не текущая волна.

### 4.2 Протоколы

vladossVPN поддерживает VLESS/Reality, VMess, Trojan, Shadowsocks, SOCKS, Hysteria2, TUIC и XHTTP. У Hiddify есть WireGuard, AmneziaWG, AnyTLS, ShadowTLS, SSH, NaiveProxy, Mieru, WARP и Psiphon; у NekoBox — WireGuard, AnyTLS, ShadowTLS, SSH, NaiveProxy и Mieru.

**Что делать:** WireGuard и AmneziaWG — самые востребованные для самохостинга и обхода. AnyTLS — для маскировки. Добавлять после стабилизации текущих волн, с тестами конфигов и лицензионной проверкой.

### 4.3 Шлюз и раздача интернета

У Hiddify есть connection sharing, у v2RayTun — ТВ-клиент. У vladossVPN только RFC. Это блокирует сценарий «телефон как точка выхода для ТВ».

**Что делать:** волна 2 по плану: отдельный порт, пароль в EncryptedSharedPreferences, QR, запрет публичных интерфейсов, автоотключение при смене сети. Не включать в golden path.

### 4.4 Переезд из конкурентов

Ниша свободна: никто не импортирует профили из другого клиента. vladossVPN уже умеет читать base64/URI, Clash YAML и sing-box JSON, есть QR. Нужен только экран миграции, детектор формата и отчёт.

**Что делать:** волна 2, после Доктора. Это дешёвая и заметная функция.

### 4.5 Доктор подключения

Сейчас ошибки понятные, но разрозненные. Конкуренты тоже не ведут по шагам. Волна 1c может дать полноценное преимущество: подписка → профиль → DNS → TCP → TLS → прокси → TUN → трафик → сервисы, с лечением по кнопке.

**Что делать:** волна 1c по плану, с `SAFE_AUTO` и `REQUIRES_CONFIRM`.

### 4.6 Профили под задачу и гибкая маршрутизация

Три пресета — хорошо для новичка, но мало для опытного пользователя. Happ управляет маршрутизацией из подписки, Hiddify даёт региональные правила, v2rayNG — geoip/geosite.

**Что делать:** волна 3: «Стриминг», «Работа», «Приватность», «Обход» как комбинации маршрутизации, split tunneling, dual path и пресетов устойчивости. Не превращать главный экран в панель управления.

### 4.7 Режим прокси без VPN

v2rayNG, Hiddify и NekoBox умеют работать как локальный прокси без TUN. vladossVPN всегда поднимает VPN. Это мешает использовать клиент на ТВ, в эмуляторе и для отладки.

**Что делать:** после шлюза — режим «только прокси» с явным предупреждением, что трафик приложений не защищён.

### 4.8 Подписочная экосистема Happ

Happ поддерживает заголовки `subscription-userinfo`, `profile-title`, `support-url`, `announce`, `fallback-url`, `new-url`, управление per-app, автопингом и фрагментацией из подписки. vladossVPN читает `subscription-userinfo`, но не поддерживает fallback URL и объявления.

**Что делать:** добавить безопасные заголовки: `profile-title`, `support-url`, `announce`, `fallback-url`. Не выполнять управляющие команды из подписки без согласия пользователя.

### 4.9 Языки

vladossVPN — русский и английский. Hiddify — 30 языков. Для русскоязычной аудитории это не блокер, для роста — ограничение.

### 4.10 Доказанная надёжность

Логика роуминга и батареи есть, но нет публичных замеров: сколько разрывов на Wi-Fi↔LTE, сколько энергии за ночь, как ведут себя Xiaomi/Samsung/Huawei. Без device-тестов это преимущество только на бумаге.

### 4.11 Автопилот пока нельзя включать

В v1.0.831 автопилот выключен сознательно. Независимый аудит нашёл medium: в режиме рекомендаций автоматическая попытка сохраняет пресет, но останавливается на экране рекомендации и не подключается. До включения флага нужно:

- обходить рекомендательный шлюз для автоповтора;
- сделать планирование шага однопоточным;
- отменять висящий шаг при ручном Connect;
- добавить тесты на `ConnectRequested(userInitiated=false)` и политику автопилота;
- проверить на устройстве применение пресета после перезапуска ядра.

### 7.1 Что усиливаем в волне стабильности

1. **Экран выключен — проверки реже.** `BatteryPolicy` получает третий вход `screenOff` и множитель к интервалу. Это прямой ответ на 40 % разряда у Hiddify и не требует изменения UX.
2. **Ограниченные коллекции.** Окно недавних падений эндпоинтов получает жёсткий потолок, чтобы долгая сессия с частыми переподключениями не растила память.
3. **Монотонные интервалы.** Кулдауны и окна внутри процесса считаются по `SystemClock.elapsedRealtime()`, а не по стенным часам: перевод времени и NTP-скачок больше не ломают баны и гистерезис.
4. **Честный «подключено».** Отдельный тест фиксирует, что состояние Connected невозможно без успешной проверки трафика, — это наш ответ на главную жалобу на Hiddify.
