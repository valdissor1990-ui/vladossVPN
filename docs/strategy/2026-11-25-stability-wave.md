# Волна стабильности: что взяли из слабых мест конкурентов

**Дата:** 2026-11-25
**Ветка:** `task/stability`
**Источники:** открытые issues `hiddify/hiddify-app` и `2dust/v2rayNG` (GitHub API, ноябрь 2026) + собственный код vladossVPN.

## 1. Слабые места конкурентов, которые мы забрали как требования

| Что ломается у конкурента | Подтверждение | Наше требование |
|---|---|---|
| Долгая сессия на заблокированном экране съедает батарею | Hiddify: «40 % разряда на Android 14», оптимизация батареи для приложения выключена | При выключенном экране интервал проверок растягивается, а не остаётся прежним |
| «Подключено» без интернета | Hiddify: статус Connected и пинг 466 мс, но Telegram не открывается | Состояние Connected невозможно без успешной проверки трафика |
| Приложение зависает после простоя | Hiddify: через час бездействия приложение не открывается до принудительного закрытия | Никаких новых потоков и блокирующих вызовов в горячем пути; все бюджеты времени ограничены |
| Цикл перезапусков ядра | Hiddify на десктопе: счётчик перезапусков 37 000+ | Конечное число повторов и честная ошибка вместо бесконечного цикла |
| Медленная проверка задержки | v2rayNG #6479: Real Delay очень медленный для кастомных Xray JSON | Проверка ограничена по времени и не блокирует UI |

## 2. Что изменено в коде

### 2.1 Экран выключен — реже проверки

- `AutoSwitcherConfig.screenOffIntervalMultiplier = 2`.
- `BatteryPolicy.isScreenOff()` читает `PowerManager.isInteractive`.
- `BatteryPolicy.healthCheckIntervalMs(context)` учитывает режим: системная экономия > режим экономии > обычный, затем множитель за выключенный экран.
- `AutoSwitcher` спит не одним `delay`, а срезами не длиннее 60 с (`MAX_MONITORING_SLICE_MS`) и пересчитывает интервал перед каждым срезом. Поэтому после разблокировки проверки возобновляются не позже чем через минуту, а не через 20 минут.
- Проверки: `BatteryPolicyTest.screenOff_stretchesEveryModeButKeepsPrecedence`, `screenOn_keepsConfiguredCadence`, `AutoSwitcherMonitoringTest`.

Итог: 3 мин → 6 мин в обычном режиме, 10 мин → 20 мин при системной экономии. Радиомодуль просыпается вдвое реже, логика переключения не меняется.

**Граница честности:** реакция на мёртвый сервер при saver + заблокированном экране может занимать до получаса с учётом подтверждений (`serverDegradationConfirmations = 3`), а не минуты. Это осознанная плата за батарею: разблокировка возвращает обычный каденс в течение минуты, а ручная проверка сервисов доступна сразу.

### 2.2 Окно недавних падений эндпоинтов

- `ConnectionCoordinator` считает окно 75 с по `System.nanoTime()`: перевод часов и NTP-скачок больше не продлевают и не обнуляют окно.
- Жёсткий потолок `MAX_RECENT_FAILURES = 24`: долгая сессия с частым fallback не растит список.

### 2.3 Честный «подключено»

Поведение не менялось — оно уже сильнее, чем у Hiddify. Зафиксировано тестом `uncorrelatedTrafficValidationResult_cannotPromoteConnectionToConnected`: результат проверки без актуального поколения не переводит соединение в Connected.

## 3. Что сознательно не делали

- **Не добавляли периодическую перепроверку трафика в фоне.** Это ещё один источник пробуждений; при жалобе «интернета нет» работает Доктор и ручная проверка сервисов.
- **Не трогали persisted-баны `AutoSwitcher`.** Они должны переживать перезапуск процесса, поэтому остаются на стенном времени; монотонность применена только к внутрипроцессному окну.
- **Не меняли `TRAFFIC_TIMEOUT_MS` Доктора.** Шаг ограничен сверху, а проба сама ограничивает сокеты; менять бюджет без device-замера — гадание.

## 4. Как проверить на устройстве

1. Включить VPN, заблокировать экран на 30 минут, затем `adb shell dumpsys batterystats` — сравнить wakeups с прошлой сборкой.
2. Разблокировать: статус должен остаться Connected, проверка сервисов отвечать.
3. Перевести время вперёд на час и вернуть назад во время сессии: бан-листы и переключения не должны сойти с ума.
